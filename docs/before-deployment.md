# Before making Nails by Eurie public

1. **Agree on the business details with Eurie.** Confirm the Small, Medium, and Large tip numbers for the exact tip brand, shape, and length she uses. The current presets are provisional. Decide the maximum sets she can actually make each day, how many days she needs, handover places, delivery method, and who pays the courier. Put these into Shop settings and the checkout wording.
2. **Check every price.** The 530 reference prices are fixed at ₱100-₱250 and custom uploads at ₱250 or ₱300 based on the customer's detail choice. Eurie should review the 430 new references against material and labor cost. Gallery prices are also stored in Supabase; editing only the web file would make checkout reject an order.
3. **Confirm photo rights.** Pinterest photographs are references, not Eurie's work. Obtain permission for any photograph you plan to keep on a public commercial site, or replace it with a photo you and Eurie own. Keep the source credits accurate. The 530-image collection is suitable for local review while you decide which images may be published.
4. **Test sign-in on the final domain.** In Google Cloud, use the Supabase provider callback URI. In Supabase Auth, add the exact deployed `/auth/callback` URL and set the final Site URL. Test a fresh Google account, both admin accounts, sign-out, and sign-in return from the gallery. Keep other providers disabled.
5. **Run a real order rehearsal without charging or making a set.** Check design selection, displayed total, `+639XXXXXXXXX` and `09XXXXXXXXX` entry, handover and delivery, receiving date, and the confirmed order in both customer and Artist desk views. Test a full date and an invalid number. Then test sizing confirmation, production, handover/courier updates, cash receipt, cancellation, and private-photo deletion with disposable test accounts and test orders.
6. **Check privacy and access.** A customer must see only her own hand photos, saved sizing, and orders. The two admins should see the artist tools; another Google account must not. Check the retention/deletion wording, Supabase storage limits, and database backup/export plan. Never put a Supabase secret key or Google client secret in the site build.
7. **Check the public site on a phone.** Make sure the checkout fits the screen, the submit button stays reachable, all 530 photo thumbnails load in batches, and links open the intended Pinterest pin or board. Confirm contact details display correctly after placing an order.
8. **Build and publish only when the above is settled.** Run `npm test` and `npm run build`; deploy the static `dist` files, set the two public `VITE_` environment variables, and retest the deployed URL. Hosting has been postponed until you create the account/repository you want to use. The local app is not a public storefront yet.

The client uses Zod to validate inputs and give prompt errors. The database still checks ownership, roles, price, quantity, and Philippine mobile format because browser validation can be bypassed. Supabase RPC sends values as data, and the React UI renders customer text as text. Those are the controls that protect against SQL injection and XSS; validation alone would not be sufficient.
